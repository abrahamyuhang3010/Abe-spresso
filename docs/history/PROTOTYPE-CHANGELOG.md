## 2026-09-19：正式版架构设计（尚未实现）

正式版按 **三个无数据库权限的 Agent + 一个工作流 + 一个受配额控制的发布器** 设计：

- A 筛选/事件归并 → B 选出 Top 5 + 7 → 代码校验证据 → C 按需复核异常 → 人工批准 → Publisher 发布。
- 候选、中间评分和过程日志不进入 D1；内容库仅提交批准的最终 12 条、期刊及必要发布指针。
- 所有 D1 访问通过共享 QuotaBroker；用户收藏/已读按真实变化合并，不能绕过出版链路的账号级预算。
- 公开 Today / Archive / 详情读取版本化静态资源，正常阅读不查询 D1、不调用模型。
- 项目硬上限为 5,000,000 行读/UTC 日、100,000 行写/UTC 日、D1 总量 5 GB；常规预算 4,000,000 / 80,000、容量目标 ≤4 GB。实际行写包含索引等成本，不能把一次 batch 视为一次行写。

## 边界与设计

当前标题与短摘录均来自真实原文。2026-09-14 是设计示例期号，不是原始新闻发布日期；每条分别显示真实日期。来源直达对应文章，但不代表对发布方主张进行了独立事实核验。图片均标为主题配图。

参考用户指定 Reuters 的新闻编辑式视觉方向（刊头、多栏、细分隔线、图文层级），不复制商标与文章。此前原型任务访问 Reuters 时曾遇到设备验证；2026-09-15 设计规范任务已成功检查 Reuters 与 TechCrunch 的可见首页。仅提炼设计原则，未逐像素复刻；详见 `design/REFERENCES.md`。

字体规范已于 2026-09-15 更新：中英文标题和正文统一无衬线，英文 Barlow（本地文件），中文 Noto Sans SC（未安装时回退思源黑体 / 苹方 / 微软雅黑）。不依赖远程字体请求；完整中文字体分片尚待发布前补齐。

全部用户交互是演示：不创建真实账号、不收集邮箱、不声称云端保存。退出演示清除收藏与阅读进度。若浏览器限制 localStorage，则降级到当前页面会话并提示。
