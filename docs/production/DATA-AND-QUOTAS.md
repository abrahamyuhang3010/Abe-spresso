# 正式版数据、配额与发布协议

日期：2026-09-19。状态：**设计基线，尚未创建数据库、迁移或云服务**。

配套：[整体架构](ARCHITECTURE.md)、[Agent 契约](AGENT-CONTRACTS.md)。以下表名、命令和阈值是实现约束，不是当前原型已有能力。平台事实见文末官方来源；其余为本项目设计决策。

## 1. 配额口径与安全余量

项目硬上限：**5,000,000 行读 / UTC 日、100,000 行写 / UTC 日、D1 总存储 5 GB**。本方案即使采用付费 Workers，也继续自行执行该上限，不把付费超额计费当成扩容许可。

必须区分：
- 行读取按扫描量统计，不是 API 次数或返回条数；`LIMIT 12` 不保证只读 12 行。
- 插入、更新、删除均可能计入行写；修改索引字段会增加写入。批处理减少往返，不把 12 行变成一次计费行写。
- 表和索引均占存储；控制台、Wrangler、迁移与维护产生的用量也不能排除。[S1]
- Free 额度每天 UTC 00:00 重置；Free 单库上限为 **500 MB**、每账号最多 **10 库**，不能创建一个 5 GB 的 Free 单库。[S1][S2]

### 1.1 每日预算分配（设计上限，不是预测消耗）

| 工作域 | 行读预算 | 行写预算 |
|---|---:|---:|
| 最终内容发布、核对、有界重建 | 100,000 | 1,000 |
| 用户收藏、已读、差量同步 | 3,200,000 | 70,000 |
| 管理、维护、迁移 | 700,000 | 9,000 |
| **常规总预算** | **4,000,000** | **80,000** |
| **未分配安全余量** | **1,000,000** | **20,000** |

- 每个工作域用完自己的预算即拒绝新操作；不能自动借用其他域。
- 账号任一维度达到硬额度 80%：告警，停止非必要维护和后台同步；安全余量默认不发放。
- 达到 90%（4,500,000 / 90,000）：冻结全部常规 D1 准入，包括常规出版；只有明确批准且已预留预算的恢复命令可执行。
- 达到项目硬上限，或无法确定剩余额度：D1 路径 fail-closed。公开静态阅读保持可用，写入留在待同步/待发布状态。
- 预算比较必须包含**已消耗 + 未结算预留**，不能只比较已完成查询。

这些阈值不代表无限用户规模。示例：若 2,000 日活用户各产生 6 次合并后的真实变化、每次实测平均 2 行写，则约 24,000 行写/日；10,000 日活在同一假设下就是 120,000，已经超标。这里的“2”只是演算假设，必须用实际 schema、索引和查询元数据替换。

## 2. 最小数据模型

建议起步使用两个逻辑数据库 `CONTENT_DB` / `USER_DB`，隔离职责；**仍共享账号级读写及存储预算**。不预先建满十个分片，也不把分库视为增加免费总额度。

### 2.1 CONTENT_DB：只有批准的最终版本

| 表 | 核心字段/键 | 写入规则 |
|---|---|---|
| `articles` | `(article_id, article_version)`；原文标题、短摘录、来源 URL/发布方、日期及精度、分类/角色、内容哈希、最小证据摘要、可选正文/媒体不可变引用与哈希及转载元数据 | 批准版本不可变；已存在且哈希一致则不写；同 ID/版本不同哈希拒绝 |
| `editions` | `(edition_id, revision)`；日期/时区、12 条有序引用 JSON、manifest 哈希、审批及短溯源信息 | 每个批准修订一行；引用冻结的文章版本 |
| `publication_head` | 固定频道键；desired_generation、edition/revision、catalog 哈希、预期旧 generation | 仅在静态产物完整后变更；表示希望晋升的版本，不冒充对外已生效 |

每期固定 12 条，故引用用一个小 JSON 保存，不另写 12 条关联记录。代码校验引用数量、唯一性、Top 5 + 7、稳定 `item_id/read_slot` 和全部文章版本存在；JSON 不是绕过完整性检查的理由。

- `article_id` 是跨版本稳定的文章身份，不使用显示序号；`article_version` 冻结原文摘录、日期及可选正文/媒体引用等字段。
- `edition_id` 与生产配置的出版日期/时区关联；重试沿用原 ID，不能每次生成新期刊。
- 原文缺失日期或摘录时遵守现有内容契约；不靠 Agent 补造。
- 来源白名单、采集配置、分类枚举放在版本化配置中，不每日重复写 `sources` 表。
- **不建** candidates、agent_messages、run_steps、scores、article_views、heartbeats 等 D1 表。日志和中间状态不能换个表名偷渡进内容库。
- D1 不存抓取 HTML 全文、图片二进制、模型原始长回复、embedding。详情可增加已批准的完整结构化原文与逐图批准的插图：D1 保存批准版本、资源引用/哈希和必要转载元数据，正文块和图像放入受控的不可变发布资源，不直接公开临时候选全文。

一次全新日报正常路径的**业务变更量**约为 `12 articles + 1 edition + 1 head = 14`。其中前 13 条在一个内容提交批次内，指针在静态资源就绪后另行变更。**14 不是 D1 实际行写保证**：索引、约束、纠错、失败尝试与必要维护均需测量和计入预算。

### 2.2 USER_DB：合并后的真实用户状态

| 表 | 核心字段/键 | 用途 |
|---|---|---|
| `reading_progress` | `(user_id, edition_id)`；12 位 `read_mask`、version、真实变更时间 | 一用户一期一行，已读与收藏独立 |
| `bookmarks` | `(user_id, article_id)`；is_saved、version、真实变更时间、有限版本引用 | 收藏状态及取消后的墓碑；不复制文章正文 |

`read_slot` 是期刊内稳定条目映射，不是当前排序位置。重新排序不改变既有已读含义；同一文章修订可保留槽位，替换成另一条新闻不能继承旧条目的已读位。替换策略需要显式映射/版本迁移与用户状态验证，不允许简单复用位号。

索引按真实访问路径设计：文章版本精确查询、期刊 ID/修订查询、用户期刊状态、某用户有效收藏的游标分页。收藏分页需要匹配 user/is_saved/排序键的索引，不能为了“少一个索引”扫描所有历史取消记录。索引的额外行写纳入成本上界。

不新增每次访问的 `last_seen` 写入；不全库 `%LIKE%`、大 OFFSET、逐页全表 COUNT；不为每个收藏再到 D1 查询正文，详情使用静态版本引用。

## 3. QuotaBroker：唯一 D1 执行与预算入口

建议以一个账号级逻辑协调器（Durable Object）维护预算与短期未完成请求账本。该组件不是第四个 Agent，也不承担新闻编辑。只有它持有 D1 binding；Publisher、User API、Admin API 均调用有限命令，不传任意 SQL。调用方身份由服务边界验证，不能信任客户端传来的 role/user_id。[S5]

### 3.1 准入顺序

```text
验证调用方与命令权限
 → 校验有限参数、批次和查询版本
 → 持久化预留该命令的读/写成本上界
 → 执行白名单参数化查询
 → 读取每条结果 meta.rows_read / rows_written
 → 持久化实际消耗并结算预留
 → 返回已确认结果
```

- **查询目录**为每条命令绑定 schema/index 版本、最大参数数、最大批次、经验证的执行计划及保守成本上界。只有返回条数上限不够；没有可靠扫描上界的查询不准进入生产路径。
- 同时约束在途请求总量、单用户速率、各工作域日预算。读/写两项都要预留，包括“查询是否变化后再写”的读取。
- D1 `meta` 提供行读写、`size_after` 和 `total_attempts` 等信息，用作实测/结算；`changes` 不能替代实际行写指标。自动重试也必须覆盖在预留上界内；实际 SDK/平台对重试计量的聚合口径须验证，不能只看最后一次返回值而漏算尝试。[S3]
- DO 中保留短期请求预留和必要幂等状态，完成后聚合与清理；不为每条查询再向 D1 写计数器。DO 自身也有存储、操作和费用预算，不能声称全部写入消失了。
- 若实际成本超出目录上界，立即停止该命令并熔断相关域，重新评测；上线前须在最大允许数据规模、索引及冲突路径下验证上界。
- 单个协调器的吞吐与延迟要压测；后续如拆分执行器，只能使用预先划拨且不可重复消费的配额，不能让每个 Worker 各自认为还有完整日额度。

### 3.2 崩溃、未知结果与跨日

- 先持久化 reservation，后执行 D1。D1 已成功但响应丢失时，标记 unknown 并继续占用预留，不盲目重新执行。
- 预留超时**不能自动退款**。恢复使用有预算的键查询/哈希或状态版本核对；无法恢复实际指标时保守计入预留上界，不把余量重新发放。
- 同一请求重放也可能产生读取；即使业务幂等，新的数据库查询仍需预算。
- UTC 日切不能清空旧日在途请求。首版在日切保护窗口暂停新 D1 请求并排空；任何无法确定发生在哪天的操作同时保守占用两个 UTC 日的预算，直到可核对。保护窗口须覆盖平台执行上限和未知状态处理，不用本地时区重置。
- 定期与账号级监控对账，把控制台操作、迁移、同账号其他项目纳入。监控有延迟，不作为唯一准入依据；按已知覆盖时间段对账，不能将覆盖同一查询的账本与监控总数重复相加或据旧数据退款。
- 发现未覆盖消费者、账本丢失或用量区间不确定，冻结新 D1 操作，先恢复安全边界。

**保障前提：**必须控制同账号所有 D1 消费者、查询上界及运维权限；否则不能仅靠本项目 Broker 保证账号绝不超额。建议独立生产账号或纳管所有消费者。平台限额报错只是最后防线，不是本方案的正常流控方式。

## 4. 发布协议：内容提交不等于公开晋升

D1 batch 的原子性限于数据库语句，不包含 R2 或 CDN；不能声称跨服务事务。[S6]

1. **批准包检查**：Publisher 检查签名/身份、期限、manifest 哈希、12 条、原文证据及唯一性。批准只授权这个精确版本；附带全文时同时检查正文完整性、逐图转载依据与所有资源哈希。
2. **同一期串行协调**：在 D1 之外获得有版本栅栏的协调权。重复调用携带同一 edition/revision/hash；内容提交和全局 catalog 晋升分别受控。
3. **预算与幂等核对**：Broker 预留后按键核对；已提交相同哈希则返回已有版本；不同哈希拒绝，不使用无条件 UPSERT 刷新 `updated_at`。
4. **原子提交最终内容**：在 CONTENT_DB 的一个 batch 内提交缺失的最终文章版本及期刊。冲突或约束错误不留下半期。实现需遵守每条 SQL 参数、长度、执行时间限制；不能把所有字段盲目拼成超限的单条 INSERT。[S2][S6]
5. **生成不可变产物**：从已提交版本生成当期 HTML/JSON、文章版本、当月档案及候选公开 catalog。核对完整 12 条、文件哈希和链接。私有审批/抓取字段不能进入公开资源。
6. **记录目标版本**：全部资源就绪后，经 Broker 有界 CAS 更新 `publication_head` 的 desired_generation/catalog 哈希。比较失败说明版本已变化，旧任务不得继续晋升。
7. **对外晋升**：串行晋升器通过 R2 条件写更新一个公开根 catalog 指针，引用不可变版本和按月档案。R2 `onlyIf` / ETag 条件失败时不可直接当成功。[S7]
8. **验证服务状态**：核对实际根对象的 generation/hash，再将工作流标为 `PROMOTED`。CDN 可能暂时保留完整旧版本；公开可见以实际根对象及缓存版本为准，不只看 D1 head。

根 catalog 短缓存/重验证，不可变资源长缓存；页面一次导航固定一个 catalog generation，避免 Today、新详情和旧 Archive 混搭。不在每个用户请求中读取 D1 head。完整性失败时保留上一完整公开版本。

### 4.1 恢复与纠错

| 故障点 | 恢复方式 | 不应做什么 |
|---|---|---|
| D1 已提交、渲染失败 | 按同一版本重建产物，必要读操作走配额 | 再插入 12 条新 ID |
| desired head 已更新、R2 切换失败 | 根据目标 generation/hash 重试受保护的晋升 | 把 COMMITTED 报成已上线 |
| R2 成功、确认响应丢失 | 核对根对象，已匹配则完成 | 再写 D1 状态流水 |
| 旧任务恢复时新版本已晋升 | 拒绝旧 generation | 获取新 ETag 后盲目覆盖旧内容 |
| 已发布内容发现错误 | 人工批准新不可变修订及必要更正说明 | 修改旧版原文却不留版本 |

同一时间只能有一个有效全局晋升者；未知在途晋升不能直接“释放锁”并允许下一版本穿过。条件写失败必须重新验证审批、目标 generation 和协调权，不能无限自动更新 ETag 重试。版本回退也以新 generation 明确指向获准旧内容，禁止 generation 倒退。

最终内容纠错属于批准修订，不属于候选落库。已存在的期刊/文章版本可复用，重建不重新调用模型。

## 5. 用户状态：即时本地反馈，确认后才叫云同步

1. 身份交给受管理认证服务，具体供应商待定。User API 从可信认证结果获取 user_id，校验授权和请求来源，不接受任意用户 ID。
2. 点击先更新本机状态；持久化待同步 outbox，1–3 秒内对同一键合并到最终意图。A→B→A 且未发出请求、与已确认状态相同，可直接消去；已经在途则必须按响应版本继续处理。
3. 一次最多建议 16 项，参数与扫描范围有界。按键发送 `base_version + desired_state + operation_id`；服务端检查状态，未变化不更新版本和时间戳。
4. 采用条件版本更新（CAS），每项明确返回 applied/noop/conflict；读位图变更按相同版本策略处理，不用客户端整个旧位图无条件覆盖服务器。
5. 版本冲突返回当前版本/状态，由客户端基于仍有效的本地意图重整；相同最终状态可返回 noop。过期重试不能越过新版本，自动恢复旧收藏或覆盖另一设备的“未读”。
6. 取消收藏保留小型 `is_saved=false` 墓碑和 version。清理需先定义最大离线队列期限与同步 epoch；过期 outbox 强制重新基线/提示用户，不能删除墓碑后接受任意老操作。
7. 只有 D1 成功得到确认才显示“已云同步”；配额不足返回 429/Retry-After，保持可见待同步状态并退避，不做高频轮询。不依赖页面关闭时才能发送。
8. 只获取当前期阅读状态和有界收藏游标；不每次路由切换下载全历史。认证响应不可进入公共 CDN 缓存，登出清除会话范围数据并隔离未发送操作。

完整用户删除、导出、注销流程需要单独实现和预算，不通过静默删除收藏解决容量问题。若未来增加账户表，必须加入用户域预算，不能假定认证元数据免费。

### 5.1 现有原型迁移

保留 `afi-editorial-prototype-v1` 和收藏/已读独立语义。生产同步采用新协议命名空间与明确的旧 ID → 稳定文章 ID 映射；用户主动确认后导入。未知或历史已替换的示例 ID 不自动映射到新新闻；不清空旧键，不把原型演示登录当成真实身份。

## 6. 存储预算和保留策略

### 6.1 D1 主库

- 项目常规 D1 占用目标 **≤4 GB**，保留至少 1 GB 到用户要求的 5 GB 硬边界。若同账号有其他项目，其占用一起计入。
- 若使用 Free，单库 **350 MB 告警、400 MB 停止无计划增长并启动容量处理**；不能等到 500 MB 才设计迁移。
- 初期两库不代表可使用满 4 GB；超过单库阈值后，需先设计用户稳定分片/内容档案分片及路由，验证配额后迁移。迁移期间旧库与新库同时占用空间，必须预留峰值容量与读写预算。
- 仅供量级估算：12 条/天 × 365 × 每条平均 8 KB ≈ 35 MB/年。8 KB 是假设，不包含期刊、索引、页面分配、修订和用户状态；不能用它证明全站长期不会到上限。
- 按实际数据库大小监测表、索引及分配空间。DELETE 有行写成本，也不能假定删除立即让报告的数据库大小下降；空间回收/重建必须在平台支持范围内验证。
- 已发布内容、有效收藏不静默淘汰。到容量边界暂停非必要增长，提示用户/编辑并提交可审计的迁移或保留政策方案。

### 6.2 辅助对象与流程状态

| 数据 | 建议位置 | 保留策略 |
|---|---|---|
| 候选包、采集检查点、短证据 | 私有 R2 | 默认 7 天；有字节上限，审批最长 48 小时，超时失效 |
| 调试摘要/失败诊断 | 私有短期日志或 R2 | 默认 14 天；脱敏、采样，不含隐藏推理或完整用户令牌 |
| 已发布最小证据、批准来源 | D1 最终记录及必要私有版本对象 | 与对应最终版本生命周期一致，不随候选 TTL 清除 |
| 公开 HTML/JSON/按月索引 | 独立公开发布桶，通过 Public Worker 交付 | 版本化；可从最终内容重建，清理不能破坏有效引用 |
| 工作流步骤与预算预留 | Workflows / DO | 小型键、哈希和有限状态；按平台能力核验留存和计费 |

私有候选与公开资源必须以独立绑定/桶或可靠权限边界隔离，不能仅靠“别人不知道 URL”。不将未批准的抓取全文长期复制作为默认采集策略。已批准的全文出版资源属于版本化发布内容，不得混入私有候选桶或绕过容量限制。

**总体存储口径：**D1 5 GB 是数据库边界，不是整个 Cloudflare 系统总占用。为保守满足“总体”要求，项目另设可控辅助对象/协调状态 **≤500 MB** 的初始预算；D1 ≤4 GB + 辅助 ≤0.5 GB，另留 0.5 GB 安全空间。工作流平台托管留存、Time Travel、备份及不可控内部副本能否纳入同一物理容量口径需要上线前核对，不承诺未计量的总物理存储 ≤5 GB。

所有可控辅助存储共享上述 500 MB，而不是每个服务各有 500 MB；达到预算先停止采集、清理过期非必要数据，不无限把 D1 的数据搬到 R2。长期静态产物（包括新增的批准正文和插图）和保留证据也占这份预算。新全文资源会显著改变容量估算，必须预留其实际字节开销；预算不足则停止发布或重审为摘录模式，不自动扩容。平台留存不能随意假定可配置：工作流 checkpoint 只传对象键/哈希和小摘要，禁止将候选全文复制进每个 step 返回值。
