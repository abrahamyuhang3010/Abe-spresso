# GitHub 工程准备与发布边界

日期：2026-09-19。范围：仓库工程化，不部署 Cloudflare、不实现生产后端。

## 1. 文件边界

- 仓库保存当前可维护的源码、规范、生产蓝图、测试与有依据的历史评审记录。
- 根目录旧原型 ZIP 和设计包 ZIP 通过 `.gitignore` 保留在本机，不删除，也不作为当前版本入库。
- `.env*`、`.dev.vars*`、私钥类文件、依赖、`.wrangler/`、生成产物、缓存和新 QA 输出忽略。
- 忽略规则不是秘密扫描或访问控制：提交前仍需检查 `git diff --cached`；真实密钥不得放入任何客户端源码或静态产物。
- 只有 `scripts/site-files.json` 白名单文件进入 `dist/`。本次为 17 个文件；设计样板、文章来源台账、内部文档、测试、历史 Logo 方案不进入产物。
- `dist/` 由源文件构建，不作为版本库的第二套可手改源码。
- 公开 GitHub 仓库内的文件本身可被访问。`dist/` 隔离只控制未来网站发布边界，不让已入库资料变成私密文件。

## 2. 可复现工具链

- Node 24.19.0（`.nvmrc`），npm 12.0.2（`packageManager` 与 engines）。
- jsdom / Playwright 使用精确版本，传递依赖通过 `package-lock.json` 固定。
- 使用 `npm ci --ignore-scripts`；不需要其他项目或本机临时目录中的模块。
- 浏览器安装是显式步骤；不会在 npm 依赖生命周期脚本中暗中安装。
- Chrome channel 为真实 Chrome stable，并未锁定其浏览器版本。因此依赖安装可复现，不承诺不同日期/操作系统的截图逐像素一致。每次验收应记录实际浏览器版本。

## 3. 本机服务与测试

- `npm run dev`：只提供白名单源码和样板。
- `npm run preview`：只提供构建后的白名单页面。
- 两者只监听 `127.0.0.1`，不枚举目录，不作为生产服务器。
- `npm run test:browser`：构建产物 → 临时端口服务 → 回归 → 关闭服务；样板通过独立 QA 服务提供，不为了通过测试把它放进生产目录。
- 新增工程测试覆盖：文件清单、字节一致、陈旧文件清理、HTML/CSS 依赖完整、符号链接/路径边界、预览暴露范围和锁文件一致性。
- 既有设计、业务、浏览器断言不删除、不跳过；浏览器脚本只增加独立样板 URL 与仓库内忽略的输出目录。

## 4. CI 与权限

- main 推送、PR、手动运行触发 CI。
- 工作流只读源码，无 Cloudflare secret，无部署动作。
- Actions 固定到完整 SHA；依赖更新应在独立变更中重新跑全套回归。
- 成功时保留网站构建产物；无论成功/失败都尝试保留已有 QA 证据。
- 不使用 `pull_request_target` 运行外部贡献者代码。
- `main` 必需检查、PR 审核人数、允许谁推送等是 GitHub 仓库设置，不因添加 YAML 自动生效。本次未自动更改这些设置。
